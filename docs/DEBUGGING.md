## 问题 1：`run-evaluator.bat` 中文全乱码，而且乱码被当成命令执行

**现象**：在 CMD 里跑 `run-evaluator.bat`，输出的中文全部变成乱码，而且开头多出两行莫名其妙的报错：

```
'鐪熺殑涓嬫锛堥偅蹇呴』鏈夋父鎴?+' 不是内部或外部命令，也不是可运行的程序
'n' 不是内部或外部命令，也不是可运行的程序
```

**定位**：
① 乱码的样子是典型的「UTF-8 字节被按 GBK 解码」（`鐪熺殑` 就是 UTF-8 的"真的"被 GBK 读出来的样子）
② `.bat` 文件本身是以 **UTF-8** 保存的，而 **CMD 的默认代码页是 936（GBK）**
③ 更麻烦的是：脚本里有几行中文 `echo` / `rem`，它们的乱码内容**被 cmd 当成命令去解析**了 → 于是报"不是内部或外部命令"

★ 注意：**功能其实没坏**（编译、起服务都正常），坏的只是显示 —— 但这两行假报错极容易让人以为脚本挂了。

**修法**：在脚本开头加

```bat
chcp 65001 >nul
```

把代码页切到 UTF-8；同时加注释说明"本文件以 UTF-8 保存"。

**怎么验证**：重跑一次，四步日志（`[1/4]` … `[4/4]`）中文正常显示，且**没有**"不是内部或外部命令"。

> ★ **教训**：凡是**被非 Python 程序读取**的文本文件（pip / CMD / git / Docker），
> 要么存成**纯 ASCII**，要么**显式声明/切换编码**。
> ★ 同一个坑在 `requirements.txt` 上也栽过一次 —— pip 用 GBK 读 UTF-8 文件，直接 `UnicodeDecodeError`。

## 问题 2：界面一直显示 30%，README 写的是 34% —— Java 少声明了一个字段

**现象**：前端评分和 README 对不上。README 说的是 7 项检查的平均分 **34%**，界面上显示 **30%**。
**两边都不报错、各自都能自圆其说** —— 这是最难查的一类。

**定位**：
① 先怀疑是前端算法实现不同（把 `calculateScore` 读了一遍，逻辑没差）
② 拿同一回合的数据手算 → 发现界面**只算了 4 项**，不是 7 项
③ 去看那三项为什么没算：`科技推进 / 文化推进 / 金币增长` 都挂在 `current.players` 上
④ 再看 Java 的 `TurnData` —— **只声明了 6 个字段，没有 `players`**
   → Jackson 反序列化时这个键根本不存在 → `playerNow` / `playerNext` 都是 `undefined`
   → `if (playerNow && playerNext)` 直接跳过 → **三项永远不执行**
⑤ 而前端是**静默跳过**：不报错、界面照样出分，只是从 7 项变成 4 项

**修法**：补 `PlayerInfo` 模型，Java 侧在 `TurnData` 里声明 `players` 字段。

**怎么验证**：界面 7 项齐全、平均 **34%**、前后期 **40% / 32%** —— 和 `analysis/compare_loose.py` 的脚本复算**对上了**。

> ★ **教训**：这类 bug 最难查，因为**两边各自都自洽，谁都不报错，只有数字对不上**。
> 所以"**指标必须能由脚本复算**"这条规矩不是洁癖，是唯一能发现这类问题的办法。
